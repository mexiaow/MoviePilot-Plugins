# 金山文档新剧提醒

定时解析金山文档（KDocs）追剧表，在**有新剧出现**时发送一条 Telegram 提醒。

每部剧只提醒一次，与更新到第几集无关；行为与「新剧雷达」类似。

- 插件 ID：`KdocsEpisodeNotify`
- 监控区段：国产剧、国外剧（固定，如需调整请修改源码中的 `WATCH_SECTIONS`）
- 依赖：`openpyxl`（由 `pyproject.toml` 声明，安装插件时自动安装）

## 配置

| 配置项 | 说明 |
| --- | --- |
| 启用插件 | 开启后按 cron 定时扫描 |
| 保存后立即执行一次 | 保存后立即扫描一次，用于首次验证，执行后自动关闭 |
| 定时规则 | 5 位 cron 表达式，默认 `1 21 * * *`（每天 21:01） |
| 金山文档链接 | 文档分享链接，File ID 会从链接自动解析 |
| 金山文档 Cookie | 必填，浏览器登录 kdocs.cn 后复制完整 Cookie |
| Telegram Bot Token | 形如 `123456:ABCDEF` |
| Telegram Chat ID | 形如 `-1001234567890` |
| 话题 ID | 可选，群组话题的 `message_thread_id` |

固定行为（无需配置）：

| 项目 | 取值 |
| --- | --- |
| 监控区段 | 国产剧、国外剧 |
| 已提醒记录保留 | 180 天（仅清理已从文档消失的记录） |
| 单次最多提醒 | 30 部，超出的在下一轮继续发送 |
| 消息形态 | 合并为一条，按区段分组 |
| Telegram 接口 | 官方 `api.telegram.org`，失败重试 2 次 |
| 代理 | 跟随 MoviePilot 的代理设置 |

## 判定逻辑

1. 下载文档，取 sheet 名中**年月最新**的工作表。
2. 按「本月更新【…】」切分区段，只收集国产剧、国外剧两个区段。
3. 从条目行（如 `【4K国产剧】名称 (2026)…共40集.更新22`）解析剧名、季数、年份与总集数；
   更新集数不参与判定。
4. 去重键为「归一化剧名 + 季数」，与插件自身的已提醒记录比对，不读取 MoviePilot 订阅：
   - 未记录过 → 新剧，发送提醒；
   - 已记录过 → 不再重复提醒；
   - 区段首次被扫描 → 只建立基线，不发送提醒。
5. 状态在通知发送成功后写入，发送失败时下一轮重试。

## 消息示例

```text
📺 金山文档新剧提醒
🕒 2026-11-02 21:01

国产剧
• 尚公主 (2026) 共40集
• 嫁金钗 (2026) 共30集

国外剧
• 幻视任务 (2026) 共8集

共 3 部新剧
```

## 插件详情页

每轮扫描后，详情页以表格展示本轮实际识别到的条目，便于核对抓取结果：

| 区段 | 剧名 | 集数 | 状态 |
| --- | --- | --- | --- |
| 国产剧 | 尚公主 (2026) | 共40集 | 已提醒 10-28 |
| 国产剧 | 嫁金钗 (2026) | 共30集 | 已提醒 10-30 |
| 国外剧 | 幻视任务 (2026) | 共8集 | 本次提醒 |

- 状态含义：`本次提醒`（本轮发送）、`已提醒 日期`（此前已发送或已建立基线）。
- 表格上方显示上次扫描时间、工作表名与文档中检测到的全部区段。
- 表格下方为最近 10 条提醒记录。

## Cookie 获取

1. 浏览器登录 https://www.kdocs.cn 并打开目标文档；
2. 打开开发者工具 → Network，选择任意 `kdocs.cn` 请求，复制完整的 `Cookie` 请求头；
3. 粘贴到插件配置的「金山文档 Cookie」。

Cookie 过期后日志会提示「获取下载链接失败 HTTP 401/403」，重新复制即可。Cookie 不会写入日志。

## 注意事项

- 解析依赖文档排版：区段标题为「本月更新【分类名】」，条目行以「【标签】名称 (年份)」开头。
  既无年份、又无「更新/共N集」字样的行会被判定为区段结束，日志中会输出对应行以便排查。
- 剧名或季数写法发生变化时，可能出现同一部剧被识别为两条的情况，可通过详情页的识别清单核对。
- 金山文档下载接口并非公开 API，网页改版后可能需要相应调整。
